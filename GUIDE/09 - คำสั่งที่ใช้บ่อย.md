# 🐬 MySQL

## เข้า mysql shell

```bash
docker exec -it ltms-mysql mysql --default-character-set=utf8mb4 -uroot -psecret ltms
```

> ⚠️ **`--default-character-set=utf8mb4` ห้ามลืมเด็ดขาด**
> ถ้าไม่ใส่ ภาษาไทยจะโผล่มาเป็น `?????????????????` ทั้งตาราง
> — ข้อมูลไม่ได้พัง แค่ client แสดงผลไม่ได้ (`?` 1 ตัว = ตัวอักษรไทย 1 ตัว)

ถ้าเผลอเข้าไปแล้วโดน `?` — พิมพ์ในprompt ได้เลยไม่ต้องออก:
```sql
SET NAMES utf8mb4;
```

## โหลดข้อมูลตั้งต้น (seed)

```bash
docker exec -i ltms-mysql mysql --default-character-set=utf8mb4 -uroot -psecret ltms < /home/cheetah/soft_end/database/seed.sql
```

> ⚠️ **ตอนเขียนยิ่งสำคัญกว่าตอนอ่าน** — ถ้าลืมแฟล็กตรงนี้ **ข้อมูลจะพังจริงใน DB**
> (ไทย 1 ตัว = 3 ไบต์ ถูกอ่านเป็นละติน 3 ตัว → `คณะวิศวกรรมศาสตร์` กลายเป็น 51 ตัวอักษร)
>
> `seed.sql` ใช้ `ON DUPLICATE KEY UPDATE` → **รันซ้ำได้เลย ไม่ต้องลบก่อน** ข้อมูลเก่าจะถูกเขียนทับ

## เช็คว่าข้อมูลปกติดีไหม

```bash
docker exec -i ltms-mysql mysql --default-character-set=utf8mb4 -uroot -psecret ltms -e "SELECT faculty_id, name, CHAR_LENGTH(name) FROM faculties LIMIT 3;"
```
ต้องได้ `คณะวิศวกรรมศาสตร์ | 17` — ถ้าได้ **51** แปลว่าข้อมูลพัง ให้โหลด seed ใหม่

## นับจำนวนแถวทุกตารางอ้างอิง

```bash
docker exec -i ltms-mysql mysql --default-character-set=utf8mb4 -uroot -psecret ltms -e "SELECT (SELECT COUNT(*) FROM faculties) faculties, (SELECT COUNT(*) FROM departments) departments, (SELECT COUNT(*) FROM sport_types) sport_types, (SELECT COUNT(*) FROM sport_stat_definitions) stat_defs, (SELECT COUNT(*) FROM users) users;"
```
ค่าที่ควรได้หลัง seed: **8 / 30 / 9 / 23**

# 🐳 Docker

```bash
cd /home/cheetah/soft_end/backend

docker compose up -d          # เปิด MySQL
docker compose down           # ปิด (ข้อมูลยังอยู่)
docker compose down -v        # ปิด + ลบข้อมูลทั้งหมด ⚠️ กู้ไม่ได้
docker compose logs -f mysql  # ดู log
docker ps                     # เช็คว่า container รันอยู่ไหม
```

> ⚠️ **`docker compose down -v` แล้ว up ใหม่ = DB ว่างเปล่า** ต้องโหลด seed ใหม่ทุกครั้ง
> (ตาราง 36 ตัวจะถูกสร้างอัตโนมัติจาก `schema.sql` ที่ mount ไว้ — แต่ **ข้อมูล seed ไม่ถูกโหลด** เพราะยังไม่ได้ mount)

## เช็คว่า MySQL เปิดอยู่ไหม (ไม่ต้องใช้ docker)

```bash
bash -c 'cat </dev/null >/dev/tcp/127.0.0.1/3306' && echo เปิดอยู่ || echo ปิดอยู่
```

# 🧪 ทดสอบ endpoint

## curl

```bash
# สมัครสมาชิก
curl -s -X POST http://localhost:8000/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"fullName":"ทดสอบ ระบบ","email":"test@ku.th","password":"abcd1234","gender":"male","birthDate":"2004-05-01","facultyId":1,"departmentId":1,"year":3}'

# เข้าสู่ระบบ (เก็บ token ไว้ใช้ต่อ)
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"test@ku.th","password":"abcd1234"}' | python3 -c 'import sys,json; print(json.load(sys.stdin)["accessToken"])')

# เรียก endpoint ที่ต้อง login
curl -s http://localhost:8000/api/v1/me -H "Authorization: Bearer $TOKEN"

# endpoint สาธารณะ (ไม่ต้อง token)
curl -s http://localhost:8000/api/v1/faculties
curl -s http://localhost:8000/api/v1/sport-types/3/stat-definitions
```

## สคริปต์ทดสอบชั่วคราว (ใช้บ่อยกว่า curl)

# 🚨 อาการที่เคยเจอ → สาเหตุ

| อาการ | สาเหตุที่เคยเป็น |
|---|---|
| ภาษาไทยเป็น `?????` ใน mysql shell | ลืม `--default-character-set=utf8mb4` (ข้อมูลไม่พัง) |
| `CHAR_LENGTH` เป็น 51 แทน 17 | seed เข้าไปโดยไม่ใส่แฟล็ก → **ข้อมูลพังจริง** ต้องโหลดใหม่ |
| endpoint คืน `{}` เปล่า | controller ลืม `await` หน้า service |
| 404 ทั้งที่ route ถูก | `router.get()` แทนที่จะเป็น `router.use()` ตอนติดตั้ง router ย่อย · หรือ path ลืม `/` นำหน้า |
| `ER_NO_SUCH_TABLE` แต่ typecheck ผ่าน | พิมพ์ชื่อตารางผิดใน SQL — **TS อ่านข้างใน string ไม่ออก** |
| ผลลัพธ์เรียงมั่ว | `SELECT` ไม่มี `ORDER BY` |
| `ECONNREFUSED 127.0.0.1:3306` | MySQL ไม่ได้เปิด → `docker compose up -d` |
| 500 ตอน register | `facultyId`/`departmentId` ไม่มีจริง ชน FK ([[07 - จุดที่ต้องยืนยันกับทีม]] A5) |

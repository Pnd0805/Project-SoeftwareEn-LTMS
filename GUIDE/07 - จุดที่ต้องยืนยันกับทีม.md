# 🔴 ส่วน A — DB ไม่มีที่เก็บ แต่ API ต้องใช้ (7 ข้อ · บล็อกจริง)

## A1 · `team_invitations` ไม่มี `expires_at`

**ต้นฉบับก็ไม่มี และ ERD ก็ไม่มี** — ไม่ใช่ความผิดพลาดของการแปลง

แต่ Part 3 ต้องการ:
- T09 คืน `expiresAt`
- T12 คืน `expiresAt`
- T13 ต้องตอบ **410** `INVITATION_EXPIRED`
- และ `team_invitation_status` มีค่า `'expired'` อยู่ใน DB จริงๆ ← **แปลว่าตั้งใจให้หมดอายุได้ แต่ลืมใส่คอลัมน์เก็บเวลา**

**ทางเลือก**

| | วิธี | ผล |
|---|---|---|
| **A** ⭐ | เพิ่ม `expires_at DATETIME NULL` | ตรงกับ API · ต้องมี job ไล่เปลี่ยนสถานะเป็น `expired` หรือคำนวณตอน query |
| **B** | ไม่มีวันหมดอายุ ตัด `expiresAt` ออกจาก API | ง่ายสุด แต่ค่า `'expired'` ใน ENUM จะไม่มีวันถูกใช้ |

```sql
ALTER TABLE team_invitations ADD COLUMN expires_at DATETIME NULL AFTER team_invitation_status;
```

**❓ ต้องถาม:** คำเชิญหมดอายุกี่วัน? (ไม่มีตัวเลขในเอกสารไหนเลย) และ `expired` เก็บจริงหรือคำนวณจาก `expires_at < NOW()`

## A3 · ไม่มีที่เก็บลิงก์ถ่ายทอดสด — **แต่นี่ไม่ใช่คอลัมน์ที่หายไป**

E12 คือ `PUT /matches/:id/livestream` → ดูเหมือนต้องมี `matches.livestream_url`

**แต่ต้นฉบับออกแบบไว้คนละแบบ:**
```sql
announcements.announcement_type ENUM('general','schedule_change','venue_change','result','livestream')
```
มีค่า `'livestream'` อยู่ และ `announcements` มี `match_id` อยู่แล้ว
→ **ดีไซน์ตั้งใจให้ลิงก์ถ่ายทอดสดเป็น "ประกาศประเภทหนึ่งของแมตช์"** ไม่ใช่ field ของแมตช์

| | วิธี | ผล |
|---|---|---|
| **A** | เพิ่ม `matches.livestream_url VARCHAR(500) NULL` | API ไม่ต้องแก้ · แต่ค่า `'livestream'` ใน announcements จะซ้ำซ้อน |
| **B** ⭐ | ให้ E12 เขียนลง `announcements` ที่ `announcement_type='livestream'` | ตรงกับดีไซน์ DB · ได้ประวัติ + แจ้งเตือนฟรี · แต่ `PUT` ต้อง upsert (ลบของเดิมแล้วสร้างใหม่) |

**❓ ต้องถาม:** ตกลงถ่ายทอดสดเป็น field ของแมตช์ หรือเป็นประกาศ

## A4 · `player_match_stat_values` เก็บได้แค่จำนวนเต็ม

```sql
sport_stat_definitions.data_type ENUM('integer','decimal','boolean')   -- รองรับ 3 แบบ
player_match_stat_values.value_int INT NULL                            -- แต่มีช่องเดียว
```

ถ้าต้องรองรับจริง → เพิ่ม `value_decimal DECIMAL(10,2) NULL`, `value_bool BOOLEAN NULL`

**❓ ต้องถาม:** MVP ต้องมีสถิติที่เป็นทศนิยม/boolean ไหม (เช่น "เวลาเฉลี่ย", "ได้ MVP หรือไม่")

## A5 · `facultyId`/`departmentId` — ✅ **แก้แล้ว 1 ก.ย. 2569**

Part 3 เขียนกำกับ A01 ไว้ว่า:
> `facultyId`/`departmentId`/`year` เป็น self-report ตาม AS-04 — Hard Filter (P01) พึ่งข้อมูลนี้ **ไม่ตรวจกับฐานทะเบียนจริง**

แต่ `ltms_database.md` มี FK:
```sql
FOREIGN KEY (faculty_id) REFERENCES faculties(faculty_id)
```

**ผลจริงที่ทดสอบแล้ว:** ส่ง `facultyId: 99` ที่ไม่มีในตาราง → mysql2 โยน `ER_NO_REFERENCED_ROW_2`
ซึ่งไม่ใช่ `AppError` → `errorHandler` ตีเป็น **500 `INTERNAL_ERROR`**
= บอก client ว่า "เซิร์ฟเวอร์พัง" ทั้งที่เป็นความผิดของ client

**Part 4 ไม่มี code สำหรับกรณีนี้เลย** (ไม่มี `FACULTY_NOT_FOUND`)

### ✅ ทำแล้ว — เลือกทาง ก. (ตรวจใน service ก่อน INSERT)

`auth.service.register()` เพิ่ม 2 ด่าน **หลังเช็คอีเมลซ้ำ ก่อน `hashPassword`**
(ก่อน hash เพราะไม่ต้องเสียเวลา 0.9 วิ ให้ข้อมูลที่ยังไงก็ตก):

```
findFacultyById(facultyId)                     → null ⇒ 400 fields.facultyId
findDepartmentInFaculty(facultyId, departmentId) → null ⇒ 400 fields.departmentId
```

ใช้ `VALIDATION_FAILED` ที่มีอยู่แล้ว **ไม่ต้องขอ code ใหม่**

**🔍 เจอเพิ่มระหว่างทำ: FK อย่างเดียวไม่พอ**
`facultyId: 1` (วิศวะ) + `departmentId: 30` (สหกรณ์ ของคณะ 8) **ผ่าน FK ทั้งสองเส้น** เพราะทั้งคู่มีอยู่จริง
→ ต้องเช็คว่าอยู่**แถวเดียวกัน**: `WHERE department_id = ? AND faculty_id = ?`
สำคัญเพราะ Hard Filter (BR-08) ที่ P01 ใช้ `faculty_id` ตัดสินสิทธิ์สมัครแข่ง

**ทดสอบผ่านแล้ว 5 เคส:** ถูกทั้งคู่ → 201 · คณะไม่มีจริง → 400 `fields.facultyId` ·
ภาคไม่มีจริง → 400 `fields.departmentId` · ภาคข้ามคณะ → 400 · คณะอื่นที่ถูกต้อง → 201
ไม่มี 500 เหลือ และไม่มีข้อมูลมั่วหลุดเข้า DB

**❓ ต้องถาม:** ประโยค "ไม่ตรวจกับฐานทะเบียนจริง" หมายถึง *ไม่เช็คว่านิสิตอยู่คณะนั้นจริงไหม*
(ซึ่งถูกต้อง — เราไม่มีฐานทะเบียน) หรือหมายถึง *ไม่เช็คอะไรเลย* (ซึ่งขัดกับ FK ใน DB)

## A6 · Reference Data ไม่มี error code เลยสักตัวใน Part 4

`GET /faculties/999/departments` (R02) และ `GET /sport-types/999/stat-definitions` (R05)
ที่ id ไม่มีจริง → **Part 4 ไม่มี code ให้ใช้** (มีแค่ `USER/TEAM/TOURNAMENT/MATCH/APPLICATION/INVITATION_NOT_FOUND`)

**✅ ตัดสินใจแล้ว (31 ส.ค. 2569): ตอบเป็น error ไม่ใช่ `200 {items:[]}`**
เหตุผล: `{items:[]}` ทำให้ frontend แยกไม่ออกระหว่าง *"ไม่มีคณะนี้"* กับ *"คณะนี้ยังไม่มีภาควิชา"*

**ขอเพิ่มใน Part 4 ตามกฎตั้งชื่อของ Part 4 เอง** (§2 "`NOT_FOUND` ทั่วไปเกินไป ต้องระบุว่าอะไรไม่พบ"):

| code | HTTP | message | endpoint |
|---|---|---|---|
| `FACULTY_NOT_FOUND` | 404 | ไม่พบคณะนี้ในระบบ | R02 |
| `SPORT_TYPE_NOT_FOUND` | 404 | ไม่พบประเภทกีฬานี้ในระบบ | R05 |

**❓ ต้องแจ้ง:** คนทำ frontend + คนดูแล Part 4 ให้เพิ่ม 2 code นี้

# 🟠 ส่วน B — API กับ DB ใช้ค่า enum คนละชุด (6 จุด)

> **สำคัญ:** Part 0-1 §1.2 กำหนดไว้ว่า **"ค่า enum ไม่แปลง"** — ส่งออกไปเหมือน DB เป๊ะ
> เพราะมันคือ *ข้อมูล* ไม่ใช่ *ชื่อฟิลด์* ถ้าแปลงจะไปเทียบกับ DB ไม่ตรง
>
> ⇒ จุดเหล่านี้ **ไม่ควรแก้ด้วย mapper** แต่ควร**แก้เอกสาร API ให้ใช้ค่าตาม DB**
> (ยกเว้น B3/B4 ที่เป็นปัญหาดีไซน์จริง ไม่ใช่แค่ชื่อ)

| # | จุด | ✅ DB (ต้นฉบับ) | 📄 Part 3 |
|---|---|---|---|
| **B1** | `match_checkins.method` | `qr_onsite`, `photo_online`, `manual_by_referee` | `qr`, `document` |
| **B2** | `match_checkins.match_checkin_status` | `success`, `rejected`, `exception` | `checked_in`, `pending_verification`, `verified`, `rejected` |
| **B3** | `teams.official_status` | `Unofficial`, `Official` | `unofficial`, **`pending`**, `official` |
| **B4** | `teams.readiness_status` | `Forming`, `Ready` | `Forming`, `Ready`, **`Inactive`** |
| **B5** | `tournaments.bracket_format` | `single_elimination`, `double_elimination` | `single_elim`, `double_elim` |
| **B6** | `match_results.submitted_role` | `team_leader`, `referee` | Part 2 เขียนย่อว่า `TL`/`REF` |

**B1, B5, B6 = แค่ชื่อย่อ/ยาว** → ใช้ค่า DB แล้วแก้เอกสาร API จบ

**B2 ต้องคิด** — DB มี `exception` ที่ API ไม่มี และ API มี `pending_verification` ที่ DB ไม่มี
เดาว่า flow จริงคือ: photo_online เช็คอิน → รอกรรมการตรวจ → `success` หรือ `rejected`
แล้ว `exception` = กรณีพิเศษ (เช็คอินสาย/ระบบล่ม?) **❓ ต้องถามว่า `exception` หมายถึงอะไร**

**B3 กับ B4 เป็นปัญหาดีไซน์ ไม่ใช่ชื่อ:**
- `officialStatus='pending'` — API อยากให้ทีมโชว์ว่า "กำลังรออนุมัติ Official" แต่ DB เก็บสถานะนั้นที่
  `team_admin_requests.team_admin_request_status` แทน
  → **ทางออก: ให้ mapper คำนวณ** — ถ้ามีคำร้อง `pending` ค้างอยู่ ให้คืน `'pending'` (เป็นค่า *คำนวณ* ไม่ใช่ค่า DB จึงไม่ขัดกฎ §1.2)
- `readinessStatus='Inactive'` — DB ไม่มีค่านี้ ใช้ `deleted_at` + `deleted_reason='inactive_6_months'` แทน
  → **❓ ต้องถาม:** ทีมที่ไม่ใช้งาน 6 เดือนถูก soft delete เลย หรือควรมีสถานะ `Inactive` ก่อน

# 🟡 ส่วน C — ชื่อคอลัมน์ที่ต้องจำตอนเขียน repository

**ต้นฉบับรอบ 4 เปลี่ยนชื่อทั้งระบบ** — ถ้าเขียน SQL ตามความเคยชินจะพังทันที

## C1 · PK ทุกตารางเป็น `{tablename}_id` ไม่ใช่ `id`

```sql
SELECT * FROM users WHERE user_id = ?;      -- ✅
SELECT * FROM users WHERE id = ?;           -- ❌ Unknown column
```

แต่ **API ยังคืน `id` เหมือนเดิม** → mapper แปลงให้ (`user_id` → `id`)

## C2 · คอลัมน์ `status` เปลี่ยนเป็น `{tablename}_status`

| ตาราง | ชื่อคอลัมน์จริง |
|---|---|
| `teams` | `readiness_status`, `official_status` |
| `team_invitations` | `team_invitation_status` |
| `team_admin_requests` | `team_admin_request_status` |
| `tournaments` | `tournament_status` |
| `tournament_amendment_requests` | `tournament_amendment_request_status` |
| `tournament_applications` | **`tournament_application_status`** |
| `matches` | **`match_status`** |
| `match_checkins` | **`match_checkin_status`** |
| `match_results` | `match_result_status` |
| `tournament_referees` | `invitation_status` ← **ตัวนี้ไม่เปลี่ยน** |

3 ตัวที่ตัวหนา — **ERD ยังวาดเป็น `status` อยู่** (ต้นฉบับทำ rename ไม่ครบ) ถ้าดู PDF แล้วงงให้ยึด MD

## C3 · `matches.match_id` ชื่อซ้ำกับ FK ในตารางอื่น

`match_results.match_id`, `match_checkins.match_id`, `announcements.match_id` ... ล้วนชื่อเดียวกับ PK ของ `matches`
→ **ต้องใช้ table alias เสมอตอน JOIN** (`m.match_id` vs `mr.match_id`) ไม่งั้น MySQL จะบ่น ambiguous

## C4 · `updated_at` เป็น `DATETIME NULL` ไม่ใช่ auto-update

**ไม่มี** `ON UPDATE CURRENT_TIMESTAMP` → backend ต้อง `SET updated_at = NOW()` เองทุกครั้งที่ UPDATE
(ลืมแล้วจะไม่มี error แต่ข้อมูล audit จะผิด)

## C5 · `tournament_referees` ไม่มี UNIQUE — เชิญซ้ำได้

ต้นฉบับตัด `UNIQUE(tournament_id, user_id)` ออกโดยเจตนา และกำหนดว่า:

> **ทุก query ตรวจสิทธิ์ต้องดึงแถวล่าสุดเสมอ: `ORDER BY created_at DESC LIMIT 1`**

⚠️ `requireReferee` ที่ลืมข้อนี้จะเจอบั๊กแปลกๆ (คนที่ถูกเชิญ 2 ครั้ง ปฏิเสธครั้งแรก ตอบรับครั้งที่สอง จะไม่ผ่านด่าน)

📄 Part 3 F01 ยังเขียน error `ALREADY_INVITED` (409) อยู่ → **ต้องตัดออก** ตามดีไซน์ใหม่

# ✅ ภาคผนวก — 10 ข้อที่เคลียร์ไปแล้ว (เก็บไว้อ้างอิง)

ก่อนได้ต้นฉบับ เอกสารนี้เคยมี 15 ข้อ ต่อไปนี้ได้คำตอบแล้วและ `schema.sql` แก้เรียบร้อย

| เดิม | คำตอบ |
|---|---|
| `tournament_status` | `pending_approval`, `rejected`, **`private`**, **`public`**, `completed`, `auto_deleted` |
| `tournament_application_status` | มี `cancelled` + `withdrawn` ครบ |
| `team_invitation_status` | `pending`, `accepted`, **`rejected`**, `expired` (ไม่ใช่ `declined`) |
| `match_status` | **`in_progress`** (ไม่ใช่ `ongoing`) · ไม่มี `cancelled` |
| `bracket_format` | ชื่อเต็ม `single_elimination` |
| `tournaments.scope_type` | `department`, `faculty`, `university` — **คนละชุดกับ** `admin_scopes.scope_type` (`faculty`, `university_wide`) ตามที่เดาไว้ถูก |
| `bracket_nodes.bracket_type` | `winners`, `losers` (พหูพจน์) · `round` เป็น NULL ได้ |
| `sport_stat_definitions.data_type` | `integer`, `decimal`, `boolean` |
| ประวัติแก้ชื่อทีม | ไม่มี `team_edit_log` → ใช้ `audit_logs` (`action_type='team_renamed'`) |
| `tournament_referees` UNIQUE | **ไม่มี** — เชิญซ้ำได้ไม่จำกัด |

**และของแถม 3 อย่างที่ไฟล์เก่าเดาผิดจนอาจทำให้บั๊ก:**
- `match_results.match_id` ต้องเป็น **UNIQUE** (idempotency ของ S01 พึ่งข้อนี้)
- `match_checkins.verified_by_referee_id` และ `player_match_stats.recorded_by_referee_id` ชี้ไป **`users`** ไม่ใช่ `tournament_referees`
- `tournament_feedback.match_key` เป็น **generated column** `AS (IFNULL(match_id,0)) STORED` + UNIQUE 4 คอลัมน์ (แก้ปัญหา MySQL ที่ถือว่า NULL แต่ละแถวต่างกัน จนกันโหวตซ้ำไม่ได้)

## 2. แต่ละโฟลเดอร์ทำอะไร + คุยกับใคร

| โฟลเดอร์ | หน้าที่ | **import อะไรได้** | **ห้าม import** |
|---|---|---|---|
| `config/` | อ่านค่าจาก env | — | ทุกอย่าง |
| `utils/` | ฟังก์ชันช่วยทั่วไป | `config/` | service, repo, controller |
| `types/` | นิยาม type | — | ทุกอย่าง |
| `schemas/` | Zod schema | `types/` | ทุกอย่าง |
| `mappers/` | row → DTO | `types/`, `utils/s3` | repo, service |
| `repositories/` | SQL | `config/db`, `types/` | service, controller, mapper |
| `services/` | กฎธุรกิจ + transaction | repo, mapper, utils, config | controller, routes, **express** |
| `middlewares/` | ด่านตรวจ | repo, utils, config | service, controller |
| `controllers/` | HTTP ↔ ข้อมูล | service, mapper | **repo โดยตรง** ❌ |
| `routes/` | ผูก path | controller, middleware, schema | service, repo |

**เช็คตัวเองง่ายๆ 3 ข้อ:**
- เห็น `SELECT` / `INSERT` นอก `repositories/` → **วางผิดที่**
- เห็น `req` หรือ `res` ใน `services/` → **วางผิดที่**
- controller import `repositories/` ตรงๆ → **วางผิดที่** (ต้องผ่าน service เสมอ)

## 3. ไฟล์กลาง 2 ตัวที่ต้องเข้าใจ

### `src/server.ts` — จุดเริ่มโปรแกรม
มีหน้าที่เดียว: เอา `app` มา `listen()`
```
import app from './app.js'
import { env } from './config/env.js'
app.listen(env.PORT, ...)
```
> **ทำไมแยกจาก `app.ts`?** เพราะตอนเขียนเทส คุณอยากได้ `app` มาทดสอบโดย**ไม่ต้องเปิด port จริง**
> ตอนนี้ยังไม่เขียนเทสก็ไม่เป็นไร แต่แยกไว้ตั้งแต่แรกง่ายกว่ามาแยกทีหลัง

### `src/app.ts` — ประกอบร่าง
**ลำดับสำคัญมาก ห้ามสลับ:**
```
1. express()
2. app.use(express.json())          ← ต้องมาก่อน route ไม่งั้น req.body เป็น undefined
3. app.use(cors())                  ← ถ้าจะต่อ frontend
4. app.use('/api/v1', routes)       ← router ทั้งหมด
5. app.use(notFound)                ← path ที่ไม่ตรงอะไรเลย → 404
6. app.use(errorHandler)            ← ★ ตัวสุดท้ายเสมอ ไม่งั้นไม่ทำงาน
```

`errorHandler` ต้องเป็นตัวสุดท้ายเพราะ Express รู้ว่าเป็น error handler จากการที่มัน**รับ 4 พารามิเตอร์**
(`err, req, res, next`) และมันจะถูกเรียกก็ต่อเมื่อมี middleware ก่อนหน้าโยน error ออกมา

## 4. การตั้งชื่อไฟล์

ใช้ `<โดเมน>.<ชั้น>.ts` — เห็นชื่อปุ๊บรู้ว่าอยู่ชั้นไหนทันที

```
team.routes.ts   team.controller.ts   team.service.ts   team.repo.ts   team.mapper.ts   team.schema.ts
```

**ยกเว้น** `config/`, `utils/`, `middlewares/`, `types/` ที่ใช้ชื่อสั้นๆ ตรงๆ (`db.ts`, `AppError.ts`, `requireAuth.ts`)

## 5. ⚠️ กับดัก ESM ที่คุณจะเจอแน่นอนใน 10 นาทีแรก

`package.json` ของคุณมี `"type": "module"` และ `tsconfig` ใช้ `"module": "nodenext"`
แปลว่าโปรเจกต์นี้เป็น **ES Module** ซึ่งบังคับว่า:

```ts
import pool from './config/db.js';        // ✅ ต้องมี .js ถึงแม้ไฟล์จริงชื่อ db.ts
import pool from './config/db';           // ❌ Error: Cannot find module
import pool from './config/db.ts';        // ❌ ก็ไม่ได้
```

**เหตุผล:** TypeScript ไม่แก้ path ให้ตอน compile — `.ts` จะกลายเป็น `.js` ตอน build
คุณเลยต้องเขียน path ปลายทาง (`.js`) ตั้งแต่แรก มันขัดความรู้สึกแต่ถูกต้อง

อีกข้อจาก `"verbatimModuleSyntax": true` ใน tsconfig ของคุณ — **import ที่เป็น type ล้วน ต้องใส่ `type`**:
```ts
import type { Request, Response } from 'express';   // ✅
import { Request, Response } from 'express';        // ❌ error
import express from 'express';                      // ✅ (ตัวนี้เป็นค่าจริง ไม่ใช่ type)
```

## 7. `req.user` มาจากไหน

`requireAuth` เป็นคนใส่ให้ — แต่ TypeScript ไม่รู้จัก คุณต้องบอกมันใน `src/types/express.d.ts`:

```ts
import type { UserRow } from './db.js';

declare global {
  namespace Express {
    interface Request {
      user?: UserRow;   // optional เพราะ endpoint สาธารณะไม่มี
    }
  }
}
export {};
```

หลังจากนี้ `req.user?.user_id` จะมี autocomplete ให้ทุกที่

> **หมายเหตุ:** ให้ `req.user` เก็บ **row ดิบจาก DB (snake_case)** ไปเลย ไม่ต้อง map
> เพราะ middleware ตัวอื่นๆ ต้องใช้ `is_suspended`, `faculty_id` ซึ่งเป็นฟิลด์ที่ไม่ควรส่งออก API
> ตัวที่ map เป็น camelCase คือ mapper ตอนจะ response เท่านั้น

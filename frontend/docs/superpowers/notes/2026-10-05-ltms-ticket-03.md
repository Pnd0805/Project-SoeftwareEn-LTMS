Implemented directly against the approved Ticket 3 follow-up, from fixed point `912e9c7`. Tickets 04–09 remain pending.

## Delivered

- Teams appear first, with invitations and entries in a separate desktop column. Local name search, sport and Leader/Member filters intersect; Clear filters restores the loaded list. An empty filtered result differs from no membership. Filtering makes no extra API request.
- Team details use an angular Barlow poster identity with the existing logo/name/sport, cream lettering and the A palette. Members, invitations and management have distinct headings. Dense tables stay in named, keyboard-focusable scroll regions.
- Invite players focuses the existing search when the viewer is a Leader and the existing application source confirms no roster lock. Existing registration controls, payloads and permission checks are retained. View entry opens the existing tournament destination using the application identifier context.
- Existing invitation accept/decline, removal, leadership transfer and management outcomes remain visible. Cancelling a sent invitation now leaves a named outcome after its row disappears. Consequential dialogs retain the selected team/player, confirmation payload, focus containment and Escape/focus return.
- Public Player profiles have proper page headings and quieter sport/history tables. A failed stats source has Retry stats while the public identity and teams remain available. Backend profiles expose no email, birth date, age or year. Team records remain mock-only; no unsupported real-mode statistics were added.
- Temporary source failures retain usable cached data. HTTP 401/403 excludes cached private lists, members and revoked leader controls. This display safeguard changes no endpoint or server permission.

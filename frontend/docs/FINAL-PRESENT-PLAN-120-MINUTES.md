# LTMS — แผน FINAL PRESENT 2 ชั่วโมง

จัดทำ: 30 ตุลาคม 2026

ระยะเวลา: **นำเสนอและสาธิต 110 นาที + ถามตอบ 10 นาที = 120 นาที**

เล่าตามวงจรการแข่งขัน ตั้งแต่ขอจัดจนประกาศผล เพื่อให้เห็นความเชื่อมโยงของแต่ละระบบ แผนนี้อ้างอิงฟีเจอร์ใน checkout ปัจจุบัน ไม่ใช่การรับรองว่าทุก flow ผ่านการซ้อมบนเครื่องนำเสนอแล้ว

## 2. ระบบที่ควรสาธิตสดให้ครบ

- [ ] ขอจัดทัวร์ → แอดมินอนุมัติ
- [ ] สร้างทีม → สมาชิกตอบรับ → สมัครแข่งขัน
- [ ] Hard Filter ปฏิเสธผู้สมัครที่ผิดเงื่อนไข
- [ ] กรรมการตอบรับ → จับสาย/นัดแข่ง
- [ ] QR Check-in → แข่งขัน → ส่งผล → อีกฝ่ายยืนยัน → เลื่อนสาย
- [ ] คัดค้านผล → ผู้จัดตัดสิน
- [ ] Pick’em ได้แต้ม → แลก Badge → แสดงโลโก้ใน Profile
- [ ] ติดตามนักกีฬาและเปิดกระดิ่ง → รับแจ้งเตือนเหตุการณ์จริง

### เชื่อมเดโมให้เป็นเรื่องเดียวกัน

ก่อนเริ่มแมตช์หลัก ให้บัญชีผู้ชมทาย Pick’em และติดตามนักกีฬาพร้อมเปิดกระดิ่งไว้ก่อน เมื่อกรรมการเริ่มแมตช์ ให้กลับมาดูแจ้งเตือนเริ่มแข่งขัน หลังยืนยันผล ให้ตรวจแจ้งเตือนผล แต้ม Pick’em และอันดับ แล้วจึงสาธิตแลก Badge และการแสดงโลโก้ข้างชื่อ

การติดตามอย่างเดียวไม่เปิดรับแจ้งเตือน ต้องเปิดกระดิ่งรายคนด้วย และหมวด Community ของผู้รับต้องเปิดอยู่จึงจะเห็นแจ้งเตือนกลุ่มนี้

### จุดที่ควรอธิบายระหว่างเดโม

- Organizer, Referee และ Team Leader มีสิทธิ์ตามทัวร์/ทีม/แมตช์ ไม่ใช่สิทธิ์ครอบคลุมทุกการแข่งขัน
- Hard Filter เป็นเงื่อนไขที่ระบบตรวจ ส่วน Soft Filter เป็นข้อมูลประกอบการพิจารณาของผู้จัด
- ผลที่ส่งแล้วยังต้องผ่านการยืนยันตามบทบาท ก่อนนำไปอัปเดตสายการแข่งขัน สถิติ และแต้ม
- ผู้เขียนผลกับผู้ยืนยันต้องเป็นคนละฝ่ายตามกฎของโหมดการแข่งขัน
- การซ่อน Badge มีผลต่อสิ่งที่แสดงใน Profile โดยไม่ได้ลบรางวัลที่ได้รับ

## 3. ระบบที่เตรียมเป็นหน้าสำรองหรือคลิปสั้น

| ระบบ | จุดที่ใช้ตอบคำถาม |
| --- | --- |
| ยกเลิกทัวร์ | เหตุผลการยกเลิก การล็อกคำสั่ง และประวัติที่ยังอ่านได้ |
| ถอนทีม/ถอนตัวกรรมการ/เปลี่ยนกรรมการ | การจัดการกรณีที่ผู้เกี่ยวข้องไม่สามารถดำเนินงานต่อ |
| รายงานความคิดเห็นและการจัดการโดยแอดมิน | กระบวนการดูแลเนื้อหาและร่องรอยการดำเนินการ |
| ระงับบัญชีและปฏิเสธการเข้าถึง | การบังคับสิทธิ์ที่ Backend และข้อความที่ผู้ใช้เข้าใจได้ |
| สถิติย้อนหลัง รีวิวทัวร์ และความเป็นส่วนตัว | คุณค่าหลังจบการแข่งขันและขอบเขตการเปิดเผยข้อมูล |
| YouTube embed | การแสดงสื่อภายนอกประกอบการแข่งขัน |
| งานอัตโนมัติ | ยืนยันผลเมื่อครบกำหนดและลบหลักฐานเมื่อหมดอายุ ใช้หลักฐานทดสอบกับข้อมูลก่อน/หลังประกอบ |

ไม่ควรรอเวลางานเบื้องหลังจริงระหว่างนำเสนอ ให้ใช้ข้อมูลที่เตรียมไว้หรือคลิปจากการซ้อม และระบุว่าเป็นหลักฐานที่บันทึกไว้

## 4. บัญชีและข้อมูลที่ต้องเตรียม

### บัญชีตามบทบาท

- [ ] ผู้จัดการแข่งขัน
- [ ] แอดมิน
- [ ] กรรมการตามจำนวนที่แมตช์กำหนด
- [ ] หัวหน้าทีมทั้งสองฝ่าย
- [ ] ผู้เล่นตามจำนวนขั้นต่ำของกีฬา
- [ ] ผู้ชมที่มีสิทธิ์ใช้ Pick’em/MVP ตามเงื่อนไขของกิจกรรมนั้น
- [ ] กรรมการภายนอกและผู้ใช้สำหรับกรณีปฏิเสธสิทธิ์ หากจะนำเสนอส่วนนี้

ใช้ browser profile หรืออุปกรณ์แยกสำหรับแต่ละบทบาทหลัก เพื่อให้ค้าง session ได้โดยไม่ต้องออกและเข้าใหม่ทุกขั้น

### ชุดทัวร์ที่ต้องมี

| ชุดข้อมูล | สถานะที่เตรียม | ใช้ในช่วง |
| --- | --- | --- |
| A | รอแอดมินอนุมัติ | ขอจัดการแข่งขัน |
| B | Private และพร้อมเตรียมกรรมการ/เผยแพร่ | การเตรียมทัวร์ |
| C | เปิดรับสมัคร มีทีมผ่านและไม่ผ่านเงื่อนไข | Hard Filter / Soft Filter |
| D | พร้อมจับสายหรือนัดแข่ง | สายการแข่งขันและตารางแข่ง |
| E | On-site พร้อมเช็คอินและแข่งขัน | เดโมหลักครบวงจร |
| F | Online พร้อมตรวจรูปเช็คอินและดูรหัสห้อง | ความต่างของโหมดออนไลน์ |
| G | มีข้อพิพาทรอผู้จัดตัดสิน | กระบวนการคัดค้านผล |
| H | จบแล้ว มีสถิติ รีวิว แต้ม และรางวัล | ผลลัพธ์หลังจบการแข่งขัน |
| I | ยกเลิกแล้ว | หน้าสำรองและประวัติ |

ใช้หลายชุดข้อมูลตามสถานะเพื่อคุมเวลา ไม่จำเป็นต้องสร้างทุกทัวร์และเล่นทุกแมตช์ตั้งแต่ต้นบนเวที

## 5. Checklist ก่อนวันนำเสนอ

- [ ] ยืนยัน branch/commit ที่จะใช้บนเครื่องนำเสนอ และนำงาน Point/Badge ล่าสุดไปให้ครบ
- [ ] ซ้อมด้วย FE ที่เชื่อม Backend จริง
- [ ] เตรียมฐานข้อมูลให้ตรงกับวันและเวลานำเสนอ
- [ ] ตรวจช่วงเวลาเช็คอิน เวลาเริ่ม/จบแมตช์ และกำหนดเวลาของ Pick’em, MVP และรีวิว
- [ ] ตรวจ Mailpit/การรับรหัสยืนยันและลิงก์รีเซ็ตรหัสผ่าน
- [ ] หากจะสาธิตการบังคับยืนยันอีเมลก่อนเข้าใช้ ให้ตรวจ configuration จริงก่อน
- [ ] ตรวจ Object Storage และไฟล์จริงที่จะใช้ เช่น รูปเช็คอินและเอกสารกรรมการ
- [ ] ซ้อม QR บนมือถือและเครือข่ายที่จะใช้จริง
- [ ] ซ้อมแจ้งเตือนผู้ติดตาม โดยเปิดกระดิ่งก่อนเกิดเหตุการณ์และตรวจหมวด Community
- [ ] ตรวจแต้มคงเหลือและราคา Badge ให้มีตัวอย่างแลกสำเร็จ
- [ ] ตรวจ role audit และรันชุดตรวจที่เกี่ยวข้องก่อนซ้อมรอบสุดท้าย
- [ ] จดบัญชี ลิงก์ทัวร์ ลิงก์แมตช์ และลำดับการสลับหน้าสำหรับผู้สาธิต
- [ ] เตรียมภาพ/คลิปสำรองของ flow หลัก
- [ ] ซ้อมจับเวลารวมและกำหนดผู้ควบคุมเวลา

**ข้อมูลเดโมเดิมผูกกับวันที่ 9 ตุลาคม 2026** จึงต้องตรวจและเตรียมช่วงเวลาใหม่ก่อนใช้กับ FINAL PRESENT รอบนี้ เอกสาร seed เป็นข้อมูลอ้างอิง ไม่ใช่การยืนยันสถานะฐานข้อมูลปัจจุบัน หลีกเลี่ยงการ restore ฐานระหว่างสาธิต เพราะจะย้อนข้อมูลที่เพิ่งดำเนินการไปแล้ว

Mailpit แสดงการรับเมลในสภาพแวดล้อมทดสอบ การส่งถึงผู้ให้บริการอีเมลจริงเป็นการตรวจอีกส่วนหนึ่ง

## 6. วิธีคุมเวลาเมื่อเริ่มเกินกำหนด

1. รักษาเวลาเดโม On-site ครบวงจรและช่วงถามตอบไว้ก่อน
2. ใช้ข้อมูลที่เตรียมไว้แทนการเพิ่มสมาชิกหรือกรอกฟอร์มซ้ำหลายรายการ
3. สาธิตการจับสายสดหนึ่งรูปแบบ ส่วนอีกสองรูปแบบเปิดดูผลที่เตรียมไว้
4. ย่อ Official Team, โอนหัวหน้าทีม, YouTube และการดูแลความคิดเห็นไปเป็นหน้าสำรอง
5. หากการเชื่อมต่อหรืออุปกรณ์ขัดข้อง ให้เปิดคลิปสำรองพร้อมอธิบายสถานะที่ควรเกิดขึ้น

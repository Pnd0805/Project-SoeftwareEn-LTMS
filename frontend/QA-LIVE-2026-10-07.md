## BE findings

1. `GET /tournaments/:id` omits `bestOf`. Creating with BO3/5 and PATCH format
   works; read-only SQL confirmed persisted values, and drawn match reads expose
   them. Add the stored nullable BO to tournament detail (and list if intended).
2. Reapplying the **same team and players in the same tournament after
   withdrawal** fails with `409 PLAYER_ALREADY_REGISTERED`. Reproduced with
   team 9036, tournament 29, prior application 37 (withdrawn); retry transaction
   rolled back. The message claims another team although this was the same
   team. Inspect player uniqueness/reservation cleanup on withdrawal/cancel.
3. Profile read uses `null` for unset contact/address, while PATCH rejects
   `null`. Clearing with empty strings works. The test account's originally
   empty values were restored as `""`, statistics as true and community as true.
   Decide whether PATCH should support null clearing consistently.

Early attempts are retained as evidence. Missing referee prerequisites and
incorrect audit/BO read assertions were corrected; they are not counted as FE
defects. The reapplication blocker remains open and was bypassed using a new
test tournament, without database edits.

### 8 · `FE-dispute-resolution-not-returned` — ⚠️ แก้แล้ว แต่ขอบเขตแคบกว่าที่ขอ — ขอแก้ต่อ
**ขอไว้:** ส่งคำวินิจฉัยของผู้จัดออกมา เพราะ migration 020 บังคับให้เขียน **"เพื่อให้ทั้งสองทีมรู้ว่าทำไม"**
**ได้:** ทั้งหกช่องครบ (ยิงแมตช์ 2 และ 11) — แต่พอผลเป็น final แล้ว **เห็นได้แค่ผู้จัด · กรรมการของแมตช์ · หัวหน้าสองทีม** ผู้เล่นธรรมดาในสองทีมไม่เห็นคำวินิจฉัย
เหตุผลของ backend มีน้ำหนัก: `disputeReason` เป็นข้อความที่คู่กรณีเขียน อาจกล่าวหาผู้เล่นตรงๆ — แต่ทั้งหกช่องถูกกั้นรวมกัน ทั้งที่ `disputeResolution` เป็นคำชี้แจงของผู้จัด ซึ่งเป็นข้อความที่ตั้งใจให้ทั้งสองทีมอ่าน
**ขอแก้ (ตัดสินแล้ว 29 ก.ย.): แยกหกช่องเป็นสองกลุ่ม**
- **คำวินิจฉัย** — `disputeResolution` · `disputeResolvedBy` · `disputeResolvedAt` → ส่งให้ **ผู้เล่นทุกคนของทั้งสองทีม** (ตาม roster ของแมตช์) นอกเหนือจากผู้จัด/กรรมการ/หัวหน้า
- **ตัวคำค้าน** — `disputeReason` · `disputeRaisedBy` · `disputeRaisedAt` → คงไว้เฉพาะผู้จัด · กรรมการ · หัวหน้าสองทีม เหมือนตอนนี้

ได้ทั้งเจตนาของ migration 020 และเหตุผลเรื่องข้อความกล่าวหาของ backend · คนนอกยังไม่ได้ทั้งหกช่องเหมือนเดิม
**หมายเหตุฝั่งเรา:** `disputeRaisedBy` / `disputeResolvedBy` มาเป็นเลข id ซึ่งสอดคล้องกับช่องคนอื่นใน S05 (`submittedBy` ก็เป็น id) — ฝั่ง FE พิมพ์ชนิดไว้ผิดเป็น object เอง จะแก้ฝั่งเรา ไม่ต้องเปลี่ยน backend

### 13 · `FE-admin-queue-shows-undecidable-rows` — ✅ แก้ตรงจุดสำหรับแอดมินคณะ · ⚠️ ขอแก้ต่อเรื่อง root

### E · report ความเห็นแล้ว **ไม่มีทางยกเลิกหรือเคลียร์** — ผู้จัดกดพลาดแล้วค้างในคิวตลอดไป
ผู้ใช้ถาม 29 ก.ย.: "ถ้าออแกไนเซอร์มือลั่นกด report แล้วควรยกเลิกได้ไหม" · ตรวจแล้วเอกสารไม่มีเรื่องนี้เลย —
SRS FR-CM-01 ขอแค่ "กลไกรายงาน + ให้ Admin ลบ" · มติ 23 ก.ย. (`OPEN_DECISIONS.md` การกำกับดูแลความเห็น) บอกว่าธง `is_reported`
**ถูกล้างเฉพาะตอนแอดมิน restore ความเห็นที่ถูกลบ** และถึงกับเขียนกรณี "ผู้จัดกด report เอง" ไว้ แต่ไม่มีทางถอน

ยิงจริงบน t19: มานะโพสต์ → `playerA1` report → ขึ้นในคิว `?reported=true` ของสมชาย (ผู้จัด) → ผู้จัดลบพร้อมเหตุผลได้ 204 ·
คนทั่วไปเปิดคิวได้ `403 NOT_ORGANIZER` ถูกต้อง — ทั้งวงจรทำงาน ขาดแค่ขาออกทางที่สาม

**ผลตอนนี้:** ความเห็นที่ถูก report โดยไม่มีมูล (ผู้จัดกดพลาด หรือคนอื่นกดกลั่นแกล้ง) **อยู่ใน "Reported only" ถาวร** ·
ผู้จัดมีทางเดียวคือลบความเห็นที่ไม่ผิดอะไรทิ้ง ซึ่งแจ้งเจ้าของ + ลง audit ว่าผู้จัดลบ — กลับหัวกับเจตนาของสามชั้นกันลบเงียบ ๆ

**ขอ: "ปิดเรื่อง report" (dismiss) ให้ผู้ตรวจ ไม่ใช่ "ถอน report ของฉัน" ให้คนกด**
- เช่น `POST /tournaments/:id/comments/:cid/dismiss-report` (guard เดียวกับ `DELETE /tournaments/:id/comments/:cid`) และให้แอดมิน `university_wide` ใช้ได้ด้วย
  → ล้าง `is_reported` · audit `comment_report_dismissed` · ความเห็นไม่ได้ถูกลบ = ไม่ต้องแจ้งเจ้าของ
- ทำไมไม่ใช่ "ถอนของฉัน": `is_reported` เป็นธงเดียวต่อความเห็น **ไม่ได้เก็บว่าใครกด** — ถ้า A กับ B กดทั้งคู่แล้ว A ถอน ธงหายทั้งที่ B ยังรายงานอยู่ ·
  จะทำแบบนั้นได้ต้องมีตารางผู้รายงานใหม่ · dismiss ใช้เหตุผลเดียวกับที่มติ 23 ก.ย. ใช้ล้างธงตอน restore อยู่แล้ว ("ผู้ตรวจดูแล้ว = เคลียร์เรื่อง")
  และครอบทั้งกรณีกดพลาดกับกรณี report ไม่มีมูล
- ฝั่ง FE: ปุ่ม Report ของผู้จัดบนทัวร์ตัวเองแทบไม่มีประโยชน์ (ผู้จัดกด Remove ได้ตรง ๆ) — จะเสนอให้เจ้าของหน้าซ่อนปุ่มนี้เมื่อ `canModerate` เป็นจริง
  ซึ่งกันกรณีกดพลาดของผู้จัดได้ตั้งแต่ต้น แต่ยังไม่ครอบ report ไม่มีมูลจากคนอื่น จึงยังต้องการ dismiss

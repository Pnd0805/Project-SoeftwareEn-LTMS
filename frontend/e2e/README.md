# E2E (Playwright) — LTMS

เทสแบบเปิดเบราว์เซอร์จริง คลิกผ่านหน้าเว็บจริง กับ **backend + MySQL จริง** (ไม่ใช่ mock)

- 27 เทส · ใช้เวลาประมาณ 1.5 นาที
- ผ่านครบ 27/27 สามรอบติดกัน (รวมหนึ่งรอบที่ล้างฐานกลับเป็นข้อมูล QA ก่อนรัน) บน Chromium

## ต้องมีอะไรก่อนรัน

1. **ฐานข้อมูลเป็นข้อมูล QA** (`database/qa-baseline.sql`) และรัน `npm run migrate` แล้ว
   - บัญชีทดสอบทุกบัญชีใช้รหัส `abcd1234`
   - ⚠️ ฐานที่ docker compose สร้างให้ครั้งแรกมาจาก `seed.sql` ซึ่ง**ไม่มี**บัญชีทดสอบ ต้องโหลดข้อมูล QA ก่อนหนึ่งครั้ง
     (ลบข้อมูลเดิมในฐานทั้งหมด):
     ```powershell
     cd backend
     $env:LTMS_MYSQL_PASSWORD = "<MYSQL_ROOT_PASSWORD ใน backend/.env>"   # สคริปต์ใช้ "secret" ถ้าไม่ตั้ง
     python ../database/qa-baseline.py restore
     npm run migrate
     ```
     ห้ามใช้ `qa-baseline.py save` — คำสั่งนั้นเขียนทับ `qa-baseline.sql` ของทีม
2. **backend รันอยู่** (`cd backend && npm run dev` ที่พอร์ต 8000) — แนะนำใส่ `JOB_INTERVAL_MS=0` ใน `backend/.env` ตอนรันเทส
   เพื่อปิดงานเบื้องหลังรายชั่วโมง ไม่ให้แก้ข้อมูลระหว่างเทส
3. **frontend รันในโหมดของจริง** — `frontend/.env.local` ต้องมี `VITE_USE_MOCK=false`
4. ติดตั้งเบราว์เซอร์ของ Playwright ครั้งแรกครั้งเดียว:
   ```bash
   cd frontend
   npm install
   npx playwright install chromium
   ```

## วิธีรัน

**แบบ dev (Vite) — ค่าเริ่มต้น**
```bash
cd frontend
npm run test:e2e
```
ไม่ต้องเปิด `npm run dev` เอง — Playwright เปิด Vite ให้ที่ `127.0.0.1:5173` แล้วปิดให้เมื่อจบ
(ถ้าเปิด Vite ไว้แล้วที่ 127.0.0.1:5173 ก็ใช้ตัวเดิม)

> ★ ถ้าเปิด `npm run dev` เองแล้วขึ้น `connect ECONNREFUSED 127.0.0.1:5173`
> แปลว่า Vite ฟังแค่ `localhost` ซึ่งบน Windows มักเป็น IPv6 (`::1`) — ปิดหน้าต่างนั้นแล้วให้ Playwright เปิดเอง
> หรือเปิดด้วย `npm run dev -- --host 127.0.0.1`

**แบบ docker compose (nginx ที่พอร์ต 8080)**
```bash
E2E_BASE_URL=http://127.0.0.1:8080 npm run test:e2e
```
(Windows PowerShell: `$env:E2E_BASE_URL="http://127.0.0.1:8080"; npm run test:e2e`)

**คำสั่งอื่น**
```bash
npm run test:e2e:ui                         # เปิดหน้าต่าง UI ของ Playwright ดูทีละขั้น
npm run test:e2e -- e2e/auth.spec.ts        # รันไฟล์เดียว
npm run test:e2e -- --headed                # เห็นเบราว์เซอร์ตอนรัน
npm run test:e2e:report                     # เปิดรายงานรอบล่าสุด (มีวิดีโอ + trace ของเทสที่พัง)
```

## ตัวแปรที่ตั้งได้

| ตัวแปร | ค่าเริ่มต้น | ใช้ทำอะไร |
|--------|-------------|-----------|
| `E2E_BASE_URL` | `http://127.0.0.1:5173` | ที่อยู่หน้าเว็บ (API ใช้ `${E2E_BASE_URL}/api/v1` อัตโนมัติ) |
| `E2E_API_URL` | `${E2E_BASE_URL}/api/v1` | ตั้งแยกถ้า API อยู่คนละที่ |
| `E2E_PASSWORD` | `abcd1234` | รหัสผ่านของบัญชี QA |
| `E2E_RESET_CMD` | (ไม่ตั้ง) | คำสั่งล้างฐานก่อนเริ่มรอบ — ดูด้านล่าง |

### ล้างฐานก่อนรัน (ไม่บังคับ)
เทสสร้างข้อมูลของตัวเองทุกครั้ง (ชื่อไม่ซ้ำ) จึงรันซ้ำบนฐานเดิมได้ แต่ข้อมูลทดสอบจะสะสมในฐาน dev
ถ้าอยากเริ่มจากข้อมูล QA สะอาดทุกรอบ:
```bash
E2E_RESET_CMD="cd ../backend && python ../database/qa-baseline.py restore && npm run migrate" npm run test:e2e
```

## ครอบคลุมอะไรบ้าง

| ไฟล์ | ทดสอบ |
|------|-------|
| `public.spec.ts` | หน้าแรกแสดงทัวร์ public · เปิดหน้ารายละเอียดทัวร์ · ทัวร์ private เปิดด้วยลิงก์ก็มองไม่เห็น · หน้าที่ต้องล็อกอิน 6 หน้าส่งไปหน้าเข้าสู่ระบบ |
| `auth.spec.ts` | ล็อกอินผ่านฟอร์ม · รหัสผิด · ช่องว่างไม่ยิง API · ออกจากระบบ · สมัครสมาชิกด้วยอีเมลภายนอกแล้วล็อกอินได้ · อีเมลซ้ำสมัครไม่ได้ |
| `tournament-request.spec.ts` | ผู้จัดกรอกฟอร์มขอจัดทัวร์ครบแล้วส่ง · วันที่สลับกันส่งไม่ผ่าน |
| `admin-approval.spec.ts` | แอดมินอนุมัติคำขอ (มีกล่องยืนยัน) · ปฏิเสธพร้อมเหตุผล · ผู้ใช้ทั่วไปเห็นแค่หน้า 403 |
| `application.spec.ts` | หัวหน้าทีมสมัครทีม (ปุ่มส่งกดไม่ได้จนเลือกผู้เล่นครบขั้นต่ำ) · ผู้จัดอนุมัติจากหน้าจัดการ · สมัครซ้ำไม่ได้ · ผู้เยี่ยมชมไม่เห็นปุ่มสมัคร |
| `team.spec.ts` | สร้างทีม · ปุ่มสร้างกดไม่ได้จนกรอกครบ · ชื่อทีมซ้ำในกีฬาเดียวกันสร้างไม่ได้ |

**ยังไม่ครอบคลุม:** เช็คอิน (ต้องมี QR/MinIO) · ส่งผล/โต้แย้งผล · จัดสาย · Pick'em/MVP · อัปโหลดรูป · อีเมล OTP (ต้องมี Mailpit)

## วิธีที่เทสทำงาน (อ่านก่อนเขียนเทสเพิ่ม)

- **ไม่ล็อกอินผ่านฟอร์มทุกเทส** — `signIn(email)` ใน `support/fixtures.ts` ขอ token จาก API แล้วใส่ใน
  `sessionStorage` ก่อนหน้าเว็บโหลด (frontend เก็บ token ใน sessionStorage ซึ่ง `storageState` ของ
  Playwright ไม่เก็บ) มีแค่ `auth.spec.ts` ที่ล็อกอินผ่านฟอร์มจริง
- **ต้องการสองคนในเทสเดียว** (เช่น หัวหน้าทีมสมัคร → ผู้จัดอนุมัติ) ใช้ `pageAs(email)` เปิดอีกหน้าต่างของอีกคน
- **ไม่ใช้ทัวร์ใน seed สำหรับเรื่องที่ขึ้นกับวันที่** — ทัวร์ใน seed ปิดรับสมัครตั้งแต่ 16 ต.ค. 2569
  `createOpenTournament()` ใน `support/api.ts` สร้างทัวร์ใหม่ที่ "เปิดรับสมัครอยู่ตอนนี้" ผ่าน API
  (ขอจัด → แอดมินอนุมัติ → เชิญกรรมการ 2 คนแล้วตอบรับ → เผยแพร่ → เปิดรับสมัคร)
- **บัญชีที่ใช้อยู่ใน `support/env.ts` ที่เดียว** — ถ้า baseline เปลี่ยน แก้ตรงนั้น
  `global-setup.ts` ลองล็อกอินทุกบัญชีก่อนเริ่มรอบ ถ้าบัญชีไหนหายจะแจ้งทันทีพร้อมวิธีแก้
- **รันทีละเทส (`workers: 1`)** — ทุกเทสใช้ฐานเดียวกัน ถ้ารันขนาน คิวแอดมิน/ผู้จัดจะมีข้อมูลของเทสอื่นปน
- เลือก element ด้วยชื่อที่ผู้ใช้เห็น (`getByRole`, `getByLabel`) ไม่ใช้ class CSS
  ⇒ เปลี่ยนหน้าตาได้โดยเทสไม่พัง แต่ถ้าเปลี่ยน**ข้อความบนปุ่ม/ป้ายกำกับ** ต้องแก้เทสตาม

## สิ่งที่เจอระหว่างเขียนเทส

- **ข้อความ error ใน `<Banner>` ไม่มี `role="alert"`** (`src/components/kit/primitives.tsx`)
  เช่น "Couldn't create the squad." ⇒ โปรแกรมอ่านหน้าจอไม่ประกาศ error ให้ผู้ใช้รู้
  (ฟอร์มล็อกอินใส่ `role="alert"` ไว้แล้ว แต่ Banner ยังไม่มี)
- **หน้า "Tournament unavailable" ของผู้เยี่ยมชม** — แถบด้านบน (โลโก้ / Sign in) ถูกดันลงมากลางจอ
  และมีที่ว่างด้านบนเยอะ ต่างจากหน้าอื่นของผู้เยี่ยมชม น่าจะเป็นเรื่อง layout ตอนแสดงหน้า error

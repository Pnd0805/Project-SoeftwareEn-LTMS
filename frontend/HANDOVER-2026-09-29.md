### R32 · A match can be finished, and only then scored

OD-26 (26–27 September) added the `finished` status and
`POST /matches/:id/finish`, and S01 now refuses a result with
`409 MATCH_NOT_FINISHED` unless the match is `finished` or `result_rejected`.
The frontend knew none of it: it opened the result form while the match was
`in_progress`, hid Match control once play started, and would have labelled a
finished match "Scheduled".

- Match control shows **Finish the match** during `in_progress` to the match's
  referees and the organizer, with a confirm step — it cannot be undone.
- The result form appears only on `finished` or `result_rejected`. During play
  the page says why it is not there yet.
- `finished` is known in every screen; `MATCH_NOT_FINISHED` and the lifecycle
  errors (`MATCH_NOT_IN_PROGRESS`, `SCHEDULE_INCOMPLETE`,
  `PREDECESSOR_DISPUTED`, `NOT_MATCH_PARTICIPANT`) read in words.
- Referees can now open check-in too, since the backend delivered it.

Verified live as `somying@ku.th` on match 13: Finish → confirm → the form
appeared → 52–47 saved, the server stored it as `submitted`. Match 13 was then
put back to `in_progress` with no result, so the reporter can repeat it.

## 4. Comment reports — where the queue is, and what is missing

The whole flow works; it was checked in the browser on t19.

1. Sign in as `playerA1@ku.th`, open `/t/19/community`, scroll to
   **Tournament comments**, press **Report** on มานะ's comment.
2. Sign in as `somchai@ku.th` (organizer of t19), same page, press **Reported
   only**. The comment carries a Reported badge.
3. **Remove** asks for a reason, which is sent to the author.

The queue is **not** under Manage → Feedback; that tab reports *reviews*. It
is the Reported only button, visible only to the organizer and university-wide
admins.

**Can a report be undone?** No document covers it. SRS FR-CM-01 asks only for
report-and-admin-removes; the 23 September decision clears `is_reported` only
when an admin restores a removed comment. So a groundless report — or the
organizer's own misclick — stays in Reported only for good, and the only way
out is deleting a comment that did nothing wrong.

What we recommend:

- **Backend:** a *dismiss* for the reviewer, not an undo for the reporter.
  `is_reported` is one boolean per comment and does not record who reported, so
  one person withdrawing would erase everyone's report.
- **Slice 2** (`LiveCommunityTab.tsx`): hide Report when `canModerate` is true
  — the organizer can Remove directly, so the button only produces the mistake —
  and add Dismiss to the Reported only view once the route exists.
